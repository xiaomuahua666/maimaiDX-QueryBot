# main 推送飞书通知

`.github/workflows/notify-main-push.yml` 会在代码推送到 `main` 后发送飞书卡片，内容包括：

- commit ID、提交摘要、作者与推送者；
- GitHub 提交与 Actions 运行链接；
- 生产 Bot 的进程状态、PID、运行时长、QQ 连接状态和已部署 commit；

工作流会先等待提交部署。如果提交已部署但 QQ 尚未连接，会立即发送黄色“已部署、等待 QQ 连接”卡片，
随后继续轮询；连接成功后再发送绿色“已部署、QQ 已连接”卡片。如果第一次状态检查已经显示 QQ
连接成功，则只发送绿色卡片，不发送黄色中间通知。生产状态通过受限 SSH 密钥读取；该密钥只能运行
`scripts/report_bot_status.sh`，不能在服务器上执行其他命令。

## GitHub 配置

在仓库 `Settings > Secrets and variables > Actions` 中配置：

| 类型 | 名称 | 必填 | 说明 |
|------|------|------|------|
| Secret | `FEISHU_WEBHOOK_URL` | 是 | 飞书群自定义机器人的 Webhook URL |
| Secret | `FEISHU_WEBHOOK_SECRET` | 否 | 机器人启用“签名校验”时填写的密钥 |
| Secret | `BOT_STATUS_SSH_KEY` | 是 | 仅用于状态查询的 SSH 私钥 |
| Secret | `BOT_STATUS_SSH_KNOWN_HOSTS` | 是 | 生产服务器固定 host key |
| Variable | `BOT_STATUS_SSH_HOST` | 是 | 生产服务器地址 |
| Variable | `BOT_STATUS_SSH_PORT` | 否 | SSH 端口，默认 `22` |
| Variable | `BOT_STATUS_SSH_USER` | 否 | SSH 用户，默认 `root` |

服务器的 `authorized_keys` 必须限制状态密钥：

```text
restrict,command="/usr/local/bin/maimaidx-report-status" ssh-ed25519 AAAA... github-actions-bot-status
```

将状态脚本安装为 `/usr/local/bin/maimaidx-report-status`，所有者设为 `root`，权限设为 `755`。

## 手动测试

配置完成后可从 GitHub Actions 页面运行 `Notify main push`，或执行：

```bash
gh workflow run notify-main-push.yml --repo AWMC-TEAM/maimaiDX-QueryBot
gh run watch --repo AWMC-TEAM/maimaiDX-QueryBot
```
