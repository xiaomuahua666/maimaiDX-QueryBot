# 飞书群内运维机器人

`scripts/feishu_ops_bot.py` 使用飞书官方 SDK 的长连接模式，不需要公开事件回调地址。

## 生产运行方式

- `maimaidx-bot.service`：systemd 管理的 QQ/NoneBot 主服务，实际由
  `/www/bot/bot_supervisor.sh` 守护；守护器每 60 秒检查 `origin/main`，快进后自动重启。
- `maimaidx-feishu-ops.service`：独立低权限用户运行的飞书运维长连接，仅通过本机 Admin API
  查询业务数据；启停 QQ Bot 只允许固定的三个 sudo systemd 命令。
- Admin API：`127.0.0.1:8099/maimaidx/admin/api`，仅供飞书服务访问，不提供公网状态页。

更新通常只需 `git push origin main` 并等待守护器自动更新；立即生效可在服务器执行
`systemctl restart maimaidx-bot.service`。飞书运维服务更新脚本后执行
`systemctl restart maimaidx-feishu-ops.service`。

## 权限模型

- 只处理 `FEISHU_OPS_ALLOWED_CHAT_IDS` 中群聊发出的消息；
- 群成员可查看运行状态、脱敏日志和错误日志；
- 只有 `FEISHU_OPS_ADMIN_OPEN_IDS` 中的用户能执行 Bot 启停、BREAK 和封禁操作；
- Bot 启停、BREAK 与封禁操作都要求二次确认；
- 一次性请求 ID 会持久化，避免卡片重试或重复点击造成重复操作；
- 日志会丢弃聊天正文，并脱敏 QQ/openid、群 ID、Token、二维码和认证信息。

管理员命令会返回确认卡片；直接点击管理卡片中的按钮也可以启停 Bot。

## 日志翻页与留存

日志卡片支持前后翻页，每页 50 行，行为如下：

- **刷新**：重新调用 `journalctl` 拉取并覆盖快照，自动回到最新一页。不点刷新就不刷新，翻页只在已缓存的快照里移动，不会触发新的 `journalctl` 调用。
- **上一页(更早) / 下一页(更新)**：在快照内前后翻页，已到边界会提示「已是最早一页 / 已是最新一页」。
- **今日6点起 / 全部**：切换留存窗口。「今日 06:00 起」只显示当前 06:00 之后的日志（次日 06:00 自然轮转到新一天，等效 24h 留存）；「全部」不设时间下限，方便排障时看更早的日志。

刷新时一次性拉取最多 5000 行原始日志（两种模式都用 `-n` 上限防 journalctl 超时），按 50 行/页可翻约 100 页。日志仍会脱敏用户标识与凭据，并过滤聊天正文、Matcher 回显、预期 404。

留存窗口通过 `journalctl --since` 实现，不写本地文件、不额外占用存储，不会造成 bot 卡顿。

## 飞书应用配置

在企业自建应用中启用机器人和长连接事件接收，并开通：

- 接收群聊中 `@机器人` 的消息事件 `im.message.receive_v1`；
- 以应用身份发送消息；
- 获取群组信息 `im:chat:readonly`；
- 卡片回传交互 `card.action.trigger`；
- 机器人自定义菜单事件 `application.bot.menu_v6`（使用菜单时）。

可在飞书控制台配置以下菜单事件键：

| 菜单 | event_key |
|------|-----------|
| 运行状态 | `ops_status` |
| 最近日志 | `ops_logs` |
| 最近错误 | `ops_errors` |
| 管理操作 | `ops_admin` |
| 业务概览 | `ops_overview` |
| 指令调用 | `ops_commands` |
| 消息量 | `ops_messages`（默认最近 1 日，可在卡片切换 1/3/7/30 日） |
| 锐评 Token | `ops_analysis_tokens` |
| AWMC API | `ops_api_report` |

菜单事件不包含群 ID，因此当前仅响应管理员；普通群成员通过群内命令和卡片按钮操作。

状态卡将进程和 QQ 网关连接分开显示：进程已运行但尚未发现 QQ Bot 时为黄色，
进程运行且 QQ Bot 已连接时为绿色。运行日志会隐藏消息正文、Matcher 回显、
重复的预期 WMC 404；错误日志仍保留真正的异常和非预期错误。消息量页面只展示
数字 QQ/群号的用户 TOP 与群 TOP，忽略未绑定的官方加密 ID，可切换最近 1/3/7/30 日。
AWMC API 页面会展示调用成功/错误、预期 404、配额触发次数；当上游提供配额元数据时，
同时显示最近配额的使用量与上限。

## 服务配置

敏感配置放在服务器 `/etc/maimaidx-feishu-ops.env`，不得写入仓库：

```env
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=xxx
FEISHU_OPS_ALLOWED_CHAT_IDS=oc_xxx
FEISHU_OPS_ADMIN_OPEN_IDS=ou_xxx
FEISHU_OPS_SUPER_ADMIN_OPEN_IDS=ou_xxx
MAIMAIDX_ADMIN_API_URL=http://127.0.0.1:8099/maimaidx/admin/api
MAIMAIDX_ADMIN_API_TOKEN=xxx
FEISHU_OPS_STATE_DB=/var/lib/maimaidx-feishu-ops/actions.sqlite3
```

QueryBot 本身需要启用仅监听本机的 Admin API：

```env
MAIMAIDX_ADMIN_WEB_ENABLED=true
MAIMAIDX_ADMIN_WEB_HOST=127.0.0.1
MAIMAIDX_ADMIN_WEB_PORT=8099
MAIMAIDX_ADMIN_WEB_TOKEN=与运维服务相同的随机管理令牌
```

生产服务应使用独立低权限用户，并只通过 sudoers 放行以下固定命令：

```text
systemctl start maimaidx-bot.service
systemctl stop maimaidx-bot.service
systemctl restart maimaidx-bot.service
```
